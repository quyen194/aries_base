# Security Policy

## Reporting a Vulnerability
If you discover a security issue, please report it responsibly.

- Do not open public issues with sensitive details.
- Instead, create a private report (e.g., email the maintainer or use a private issue template if available).
- Provide steps to reproduce, affected versions, environment details, and any proof-of-concept.

## Supported Versions
This project is under active development; we generally support the latest `dev` branch and the most recent tagged release.

## Response Expectations
We aim to acknowledge reports within 7 days and provide an initial assessment within 14 days. Remediation timelines depend on severity and complexity.

## Dependency Security
This project uses third-party libraries (e.g., `spdlog`). Vulnerabilities in dependencies should be reported upstream. We will update our pinned versions and vendored copies as necessary.
